# 構造設計

## 1. データ構造
```
|構造体（struct Word）──────────────────────┐
├── kanji (wchar_t[64]) │
├── kana (wchar_t[64]) │
├── meaning (wchar_t[128]) │
├── example (wchar_t[256]) │
├── type (int) │
├── proficiency (int) ← 熟練度（正解：++, 不正解：--） │
└──────────────────────────────────────────┘
```

## 2. 保存方式
- 単語データは `struct Word` の動的配列（g_words）としてメモリ上に保持する
- 起動時に CSV ファイル（words.csv）を読み込む
- 単語登録・修正・削除後、およびアプリ終了時に CSV へ保存する
- 文字コードは UTF-16（BOM付）で保存（WinAPI 互換）

## 3. 構成図（モジュール）
```
------------------
| main.c | WinMain / メッセージループ
------------------
        ↓
------------------

------------------
        ↓

------------------
        ↓

------------------
        ↓
------------------

------------------
```

## 4. 処理フロー

```
[ユーザー操作]
      ↓
[UI層：ui.c]
      ↓
[dictionary層：単語追加／修正／削除／検索]
      ↓
[fileio層：必要時に保存 or 起動時読込]
      ↓
[UI更新（ListView 更新、メッセージ表示、クイズ出題）]
```

## 5. エラーハンドリング

- CSV 読込失敗  
  → 「保存ファイルが見つかりません」ダイアログ

- 登録フィールドが未入力  
  → プレースホルダー表記を残す / 登録処理を実施しない

- 単語が1件もない状態でクイズ開始  
  → 「単語が不足しているためクイズを開始できません」

- 重複登録（漢字＋カナの完全一致など）  
  → 将来的にチェック可能

- 配列上限超過（最大数を超えた場合）  
  → 「登録数の上限に達しました」

## 6. 使用ライブラリ・技術

- C言語標準ライブラリ（stdio.h, string.h, stdlib.h）  
- WinAPI（GUI実装：ウィンドウ生成、コントロール配置、メッセージ処理）  
- ファイル形式：CSV形式または独自形式（テキストベース）  
- 今後の拡張候補：Orcale / MongoDBなどのDBMS
